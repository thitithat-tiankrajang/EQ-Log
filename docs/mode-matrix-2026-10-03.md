# Game mode matrix — Phase A.5 (all modes playable)

Date 2026-10-03 · worktree `EQ-Lab-live-sync` · base `4ce7c0f` (approved Phase-A UI) · Phase B not started.

Every game is played in the one approved `LiveGameShell` (`#/play/<id>`, `#/room/<id>`; Ranked through `RankedMatchPage = LiveGameScreen`). There is no offline/local-only play: without Supabase the play route shows "Online play is required". Modes differ only through the **recipient projection** the server builds (`LiveGameView`: `mode`, `yourSide`, `hostRacks`, `localHandoff/localConfirmed`, `tileDrawMode/phase`, `botSide`, `clockPolicy`, `can*` flags) and the shell's `ShellCapabilities` derived from it (`src/liveGame/shell/model.ts`). The server authorizes every command; a capability only decides whether a control is rendered.

## Known limitations (factual)

- **Recorded Pass & Play:** the local claim is per revision, so recording your own draw re-conceals the rack and needs one more "confirm handoff" by the same player. Privacy-correct; one extra tap per refill.
- **Bot/solo waiting room** says "Both players are here / A not ready · B not ready" before Launch. Works; wording is generic.
- **Completion reason** on a Result derived from History (opponent seat) names the winner only; the reason (score/surrender/timeout) is shown only to the seat that received the final projection.
- **Authur boards:** a Pro account may hold 3 active Pro boards; finish or leave Authur games during repeated manual testing.
- **Ranked page** strings are partly Thai regardless of locale (pre-existing).
