# Finite production-baseline live compatibility inventory

Baseline: `34d5ae676fc460bfff02fe142b5d76354206b903`. Dedicated branch:
`codex/live-sync-optimization-phase1`. This inventory was completed from source

## Scope and enumeration method

Read baseline versions with `git show HEAD:<path>` for changed files. Traced
`router.ts`, `app/AppRoot.tsx`, `app/NonPlayApplication.tsx`, all creation/waiting
pages, `App.tsx` gameplay callbacks and sync effects, `roomAccess.ts`, `pregame.ts`,
`game.ts`, `domain/{canonical,inventory,draft,projection}.ts`, gameplay tilebag,
timer/end-game/multiverse, `playModeTools.ts`, game-record repositories, bot
catalog/identity/requests/runtimes, Ranked client/rules/handler, Stage repository,
Stage admin, all six baseline Edge functions, and baseline SQL through 102600.
Searched baseline RPC/invoke/table references, `setGame`, `setRack`, snapshot
restore, score, turn, and session mutations; distinguished a UI callback from an
unused reducer/API. The 58 rows below are the finite compatibility checklist.
Production configuration values can override catalog defaults; this inventory
does not assert how many live production sessions currently exist. The original
enumeration preceded this round's edits; statuses below incorporate the final
closure results. See `live-security-final-compatibility-2026-10-01.md` for gate
counts, per-mode milestones, production facts, and rollout constraints.

Notation: **P** = candidate path has prior local release evidence; **B** = concrete
compatibility blocker; **R** = insecure behavior must be retired explicitly;
**N** = not a production live-game feature. All safe new gameplay paths read
`live-game/read` recipient projections (**V**), write typed trusted commands
(**C**), and use ID/revision-only broadcast (**I**). Old paths read full
`room_live.state/canonical/session`, event snapshots, or timeline (**F**), and
write full state through `commitRoomState/commit_live_game_command` (**W**).
P applies only to tested operations, never to every feature of an entire mode.

## Manual/host capability model derived from baseline

Capabilities are per room and authenticated actor; owner/admin status is never a
license to inspect another seat. Use public log/revision/line references, not
browser-supplied snapshots. Host gets neither rack, ordered bag, exchange contents,
RNG, nor historical hidden state. Player gets only their frozen seat's own rack.

| Capability                          | Actual baseline operation | Secure permission and command                                                                                                             | Disposition                                                   |
| ----------------------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Configure waiting game              | F11/F13                   | separate host/owner, before play; typed settings; server redeal                                                                           | blocker                                                       |
| Record physical own draw/correction | F27–F29                   | requires proof/authority for an actually observed draw; cannot authorize guessed bag-token probes merely because caller is host or seated | design blocker; no unsafe endpoint introduced                 |
| Record public physical placement    | F20–F23                   | seated actor's own verified intake; alternatively referee public placement tied to a player-confirmed move; server scoring/conservation   | blocked by physical intake                                    |
| Record exchange/pass                | F24/F25                   | own seat only; host may record public pass under explicit referee capability, but cannot request exchange tokens from either rack         | player commands work automatically; physical path blocked     |
| Correct public board/turn           | F36/F37/F42               | private server history reference + revision; disclosure history retained; no arbitrary rack payload                                       | blocker                                                       |
| Score/notes/stars                   | F38/F39                   | authorized host public log reference; score paused; notes bounded, no arbitrary hidden strings copied from state                          | score works; annotations missing                              |
| Pause/resume/finish                 | F31/F34/F56               | separate host or self Solo lifecycle owner; server reducer and atomic capture                                                             | Hosted automatic and both automatic Solo variants pass        |
| Retry bot/admin recovery            | F48                       | trusted outbox/lease retry; no bot seat/rack exposure                                                                                     | recovery works; browser takeover retired                      |
| Read/export/replay                  | F18/F44                   | public board/own history while live; full authorized completed Replay only after atomic terminal persistence                              | full-live export/Replay retired; own/public navigator missing |

The historical physical feature was specifically **host enters the actual rack
from a palette of true bag tokens**, not merely public board editing. Returning
that palette, accepting arbitrary host requests that test token availability, or
letting one host inspect both players on alternate turns violates the clarified
boundary. Moving that exact interaction into Edge alone does not solve it. A
working replacement must define trustworthy physical intake and correction,
preserve a complete terminal record, and pass an adaptive membership-probe test.
This candidate does not have that replacement. No product waiver is inferred.
